# Cookies and sessions

HTTP is stateless. Each request is complete on its own and the server has no memory of
the last one — which is what lets caches and proxies reason about a single request
without tracking a conversation, and is also why the web needed a workaround for
"remember who I am".

The workaround is a <Term>cookie</Term>: a value the server asks the browser to store and
send back on every later request to that site.

```http
HTTP/1.1 200 OK
Set-Cookie: __Host-sid=8f2c...; Secure; HttpOnly; SameSite=Lax; Path=/

GET /account HTTP/1.1
Cookie: __Host-sid=8f2c...
```

## The cookie is a pointer, not the data

That value is almost always a random identifier and nothing else. The real

<Term>session</Term> — who you are, what you may do, when you logged in — lives on the
server, where it can be revoked.

That indirection is what makes logging out mean something. Put the user's identity into
the cookie itself and you cannot take it back: the browser holds it, the server has no
list of what it issued, and the only expiry is the one you signed into it.

## The attributes are the whole security story

| Attribute        | Withholds the cookie from                                   | Attack it addresses     |
| ---------------- | ----------------------------------------------------------- | ----------------------- |
| `Secure`         | Any cleartext HTTP request                                  | Network interception    |
| `HttpOnly`       | `document.cookie`, i.e. all JavaScript                      | XSS reading the session |
| `SameSite=Lax`   | Cross-site POSTs and subresources                           | CSRF                    |
| `__Host-` prefix | Any weaker configuration than host-only, `Path=/`, `Secure` | Subdomain injection     |

`SameSite` deserves care, because what it does is narrower than it sounds: the
cross-site request is still **sent**, and the server still receives and executes it. What
is withheld is only the cookie — so the request arrives unauthenticated and is rejected
on that basis. That is exactly enough to stop CSRF and not one thing more.
