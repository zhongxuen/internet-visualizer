# What a network actually is

A network is not a cable. It is an agreement.

Two machines joined by a wire can pass voltage back and forth, and that is all. To
send anything meaningful they need to have settled a set of questions in advance: where
does a message start and stop, who is it for, and how does the receiver know it arrived
intact. That settlement is a <Term>protocol</Term>, and every layer of the Internet is
one.

The smallest useful version has three parts. Two <Term id="host">hosts</Term>, a link
between them, and a message with an <Term id="ip-address">address</Term> on the front:

```text
+-----------------------------------------------+
| to: 192.0.2.30   from: 192.0.2.11   len: 1400 |  <- header
+-----------------------------------------------+
| GET /index.html HTTP/1.1 ...                  |  <- payload
+-----------------------------------------------+
```

The top half is the <Term>header</Term>: fixed fields, in a fixed order, for machines.
The bottom half is the <Term>payload</Term> — the thing you actually wanted to send,
which the network carries without reading.

## Why packets, and not files

A link is shared. If one machine could hold it for the length of a whole file, everyone
else would wait for the length of a whole file.

So data is cut into <Term id="packet">packets</Term>: bounded chunks, each with its own
header, each routed independently. Many conversations then interleave on one wire, a
chunk lost to interference is resent on its own rather than restarting the transfer, and
no single sender can monopolise the link. The cost is that packets can arrive out of
order, twice, or not at all — which is precisely the mess TCP exists to clean up.

fresh <Term>router</Term> that has no memory of the ones before it. Press play and

## Latency is not bandwidth

The last idea to fix before anything else makes sense: two different things are called
"speed", and confusing them is behind most wrong guesses about why a page is slow.

|                        | What it measures                              | Fixed by                    |
| ---------------------- | --------------------------------------------- | --------------------------- |
| <Term>latency</Term>   | How long one message takes to arrive          | Being closer. Nothing else. |
| <Term>bandwidth</Term> | How much data flows per second once it starts | A fatter link               |

A page load is not one big transfer; it is dozens of small round trips, each waiting on
the one before it. That is why a fast connection on the other side of an ocean still
feels slow, and why the fastest request is always the one that is never made.
