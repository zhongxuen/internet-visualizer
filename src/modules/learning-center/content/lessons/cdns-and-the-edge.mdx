# CDNs and the edge

A <Term>CDN</Term> is not exotic. An edge server is an ordinary shared HTTP cache obeying
exactly the RFC 9111 rules from track 4 — `max-age`, `s-maxage`, ETags, 304s, all of it.
The only thing that makes it a CDN is _where_ it sits.

## The saving is distance, not work

The origin never heard about that request. Nothing was computed, nothing was queried,
and the entire cost of the page was a handful of milliseconds to a machine in the same
city.

The `Age` field is the giveaway: it says how long the edge has been holding this
response, which is information no origin would ever send about itself. A miss shows you
what was avoided:

<EmbeddedSim module="internet-simulator" scenario="cdn-miss-origin-fetch" />

The client sees one request and one response either way. Behind it, the miss paid for a
whole round trip to the origin plus the origin's own work — and the next visitor gets the
fast version because this one paid for it.

## Getting you to the nearest edge

Two mechanisms do the steering, and they work at different layers.

The first is DNS. A <Term>CNAME</Term> points your name into the CDN's zone, which hands
the CDN the right to decide the answer — the delegation from track 3, put to work. Short
TTLs let it change its mind quickly.

The second is <Term>anycast</Term>: one address advertised from many places at once, so
routing itself delivers each packet to the nearest announcement. There is nothing to look
up and no decision to make at the client.

|         | DNS steering            | Anycast                  |
| ------- | ----------------------- | ------------------------ |
| Decides | Per lookup, by the CDN  | Per packet, by routing   |
| Sees    | The resolver’s location | The client’s actual path |
| Changes | On a TTL                | On a routing update      |
