# Routing: how a packet finds its way

There is no map of the Internet, and no machine anywhere holds the route your packet
will take. Each <Term>router</Term> knows only which of its links leads _closer_ to a
given block of addresses, and forwards accordingly. The path is what emerges.

That has a strange consequence worth sitting with: the packet does not know where it is,
the sender does not know the route, and the route may differ from the one the reply
takes. Every <Term>hop</Term> is a fresh decision by a machine with no memory of the one
before it.

## The Internet is a graph of networks, not routers

Zoom out and the units stop being machines. The Internet is roughly a hundred thousand

<Term id="autonomous-system">autonomous systems</Term> — an ISP, a university, a large
company — each running whatever it likes internally and announcing to its neighbours which
addresses it can reach. That announcement protocol is <Term>BGP</Term>.

Two networks that exchange traffic directly are <Term>peering</Term>; a network that
pays somebody to reach everywhere else is buying transit. Those commercial choices, not
geography, decide the shape of the graph — which is why a CDN edge can be one hop away
and a server on the next continent fifteen.

| Traffic goes via   | Because                      | What you can measure     |
| ------------------ | ---------------------------- | ------------------------ |
| A peer             | Free, direct, usually short  | Low latency, few AS hops |
| A transit provider | Paid, but reaches everything | Longer paths, more hops  |

## What one packet experiences

Down at the level of a single packet, each hop does the same small set of things: check
the header, decrement the <Term>TTL</Term>, rewrite the link-layer addresses for the
next link, and forward. The IP addresses on the packet never change; the hardware
addresses change every single hop.
