# Asking for the page

What does your <Term>browser</Term> actually say to a website?

Once your browser has the site's number and a connection, it can ask for the page.
It asks in <Term>HTTP</Term>, the set of rules browsers and websites share. An HTTP
message is plain text that a person can read.

The browser sends an <Term>HTTP request</Term>, which works like a written order. It says
three things:

- what to do: `GET` means "send me this";
- which page: `/index.html`;
- which site: `example.com`, because one <Term>server</Term> can hold many sites.

The server sends back an <Term>HTTP response</Term>, like the reply to that order. It starts
with a <Term>status code</Term>, which is like the stamp on the reply. `200 OK` means "done,
here it is". The page itself comes after that.

Other status codes are other stamps. `404 Not Found` means the site has no such page.
`301 Moved Permanently` means the page lives somewhere else now, and the browser goes there
instead.

could read it too. The last lesson in this track shows how <Term>HTTPS</Term> fixes that.
