# Records, aliases, and delegation

A DNS answer is not "an address". It is a set of records at a name, each with a type, and
the type you asked for decides what comes back. The same name can hold several.

| Type  | Answers the question                     | Typical value         |
| ----- | ---------------------------------------- | --------------------- |
| A     | Where is this name, in IPv4?             | `93.184.216.34`       |
| AAAA  | Where is this name, in IPv6?             | `2606:2800:220:1:...` |
| NS    | Who is authoritative for this zone?      | `ns1.example.com`     |
| MX    | Where does mail for this go?             | `10 mail.example.com` |
| TXT   | Arbitrary text, usually proof of control | `v=spf1 ...`          |
| CNAME | This name is really that name            | `www.example.com`     |

The last one is different in kind from the others. Every type above it is data. A

<Term>CNAME</Term> is an instruction: stop asking about this name and start again at that
one.

## Why a CNAME cannot share a name

Because a CNAME replaces the name entirely, it must be the only record there. There is no
coherent way to say "this name is really that name, and also here is its mail server" —
the two statements contradict each other.

That has a practical consequence people meet constantly: a zone apex like `example.com`
must carry NS and SOA records by definition, so it can never be a CNAME. Only
`www.example.com` can. Providers work around it with non-standard record types that
behave like a CNAME and resolve to addresses at the server, but the underlying rule has
not changed.

## Following an alias out of the zone

A CNAME whose target is in the same zone is answered in one exchange — the server
follows the chain itself, because it can. A CNAME pointing into somebody _else's_ zone
cannot be: the walk restarts at the root and climbs down a second time, into a zone the
original operator does not control.

That is not a limitation. It is the point. Pointing your name at a

<Term>CDN</Term> hands over *who decides the answer*, which is what lets the CDN return a
different address for a visitor in Lagos than for one in Frankfurt.
