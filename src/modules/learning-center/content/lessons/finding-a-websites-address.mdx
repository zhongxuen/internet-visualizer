# Finding a website's address

How does your computer find the number behind a website's name?

A name such as www.example.com is a <Term>domain name</Term>. People can remember it.
But <Term>packets</Term> can only be sent to a number: the site's <Term>IP address</Term>.

Turning the name into the number is the job of <Term>DNS</Term>. Your computer doesn't do
the searching itself. It asks a <Term>resolver</Term>, which works like a helper who looks
up numbers for you.

No single <Term>server</Term> holds every name. So a resolver that knows nothing yet has to
ask in steps.

1. A root server says which servers look after names ending in .com.
2. A .com server says which servers look after example.com.
3. Those servers hold the real answer, and give the resolver the number.

Press play to watch a resolver with nothing written down find the number from scratch.

<EmbeddedSim module="dns-explorer" scenario="cold-cache" />

Three questions for one name takes time. So the resolver writes each answer down to reuse
it, and the saved answers are called a <Term>cache</Term>. The next time anyone asks for
example.com, the resolver answers straight away, without asking anyone else. Each answer
says how long it may be kept, so old answers don't linger forever.

The run ends with a second question about the same site. Its answer is too big for one small packet.
So the resolver asks again, in a way that can carry more.
