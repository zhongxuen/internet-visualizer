# How a name is resolved

There is no list of every domain name anywhere. No machine has one, and no machine could
keep one current. <Term>DNS</Term> answers a question nobody holds the answer to, by
asking three servers that each hold one piece of it.

Read a name right to left and you are reading a path down a tree:

```text
www.example.com.
                ^ the root (the trailing dot, almost never typed)
            ^^^ the top-level domain: who runs .com
    ^^^^^^^ the domain: delegated by .com to its owner
^^^ a name inside that owner's zone
```

Each dot is a place the tree may have been handed to somebody else. A

<Term>zone</Term> is one such slice, and every boundary between two of them is where a
referral happens.

## Recursive at the top, iterative below

Your machine asks one question and waits. The <Term>resolver</Term> does the walking:
it asks the root, which does not know the answer and says who does; it asks the
`.com` servers, which do not know either and say who does; it asks the

<Term>authoritative server</Term>, which finally answers.

| Asked         | Knows the answer? | What comes back                  |
| ------------- | ----------------- | -------------------------------- |
| Root server   | No, and never     | A referral to the TLD servers    |
| TLD server    | No                | A referral to the zone’s servers |
| Authoritative | Yes               | The record, with a TTL           |

A referral carries addresses as well as names — otherwise resolving `ns1.example.com`
would require resolving `ns1.example.com`. Those extra records are called glue, and they
are what stops the whole system from being circular.
