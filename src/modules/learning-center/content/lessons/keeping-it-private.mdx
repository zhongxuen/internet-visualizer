# Keeping it private with HTTPS

How does the padlock keep what you send private?

Your <Term>packets</Term> cross many <Term>networks</Term>, and whoever runs one can copy what
passes through. With plain <Term>HTTP</Term>, the copy is readable.

The fix is <Term>HTTPS</Term>: HTTP sent inside <Term>TLS</Term>, which works like a sealed
envelope only the recipient can open.

First, your <Term>browser</Term> and the site have a short opening exchange, a <Term>handshake</Term>.
It does two jobs.

1. **They agree a secret.** Each side sends some numbers, and both work out the same secret
   from them. Someone who sees every number still can't work it out.
2. **The browser checks the site's ID.** The site sends a <Term>certificate</Term>, like an
   ID card signed by someone both sides trust.

After that, everything is <Term>encrypted</Term>: scrambled so only the two ends can read it.

HTTPS doesn't hide everything. An observer still sees the site's name and
its <Term>IP address</Term>, because the packets need them to be delivered. They also see
when you visited, and roughly how much was sent. What stays hidden is which page you asked for,
and anything you typed into it.

The padlock beside the site's name means two things: the connection is encrypted, and the
certificate passed its checks. It doesn't mean the site itself is honest.
